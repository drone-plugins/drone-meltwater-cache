## Research

Versions verified: sbt 1.12.9 (official sbt 1.10.7 launcher), Temurin JDK 17.0.15+6, Linux amd64.

### How sbt resolves its cache

`COURSIER_CACHE=... sbt ... 'show csrCacheDirectory' update` reported the supplied absolute directory on every fixture module (evidence/research-probe.log). Official Coursier cache documentation gives Linux ~/.cache/coursier/v1, macOS ~/Library/Caches/Coursier/v1 and Windows LOCALAPPDATA/Coursier/Cache/v1. Explicit sbt settings/system properties can override the env: do not attempt to parse arbitrary Scala or JVM command lines. Relative env is process-cwd relative; plugin tests will characterize this without executing sbt. No configuration files are rewritten.

### What to cache and what not

The `https` subtree contains URL-addressed downloaded artifacts and resolution metadata, not installed JDKs or sbt boot installations (Coursier cache docs; `du -sh .cache/sbt` measured 275 MB after probe). Cache only HTTPS repositories; HTTP/file repos and custom native cache overrides are outside this increment. Exclude target (compiled/build state), .sbt (boot/global plugins), .ivy2 (Ivy/config/local publications) and credentials.sbt. Credentials normally live outside this artifact subtree; never use credentials embedded in repository URLs. Downloads may contain private artifacts; use trusted cache access. Coursier validates artifact metadata/checksums; no cross-platform native runtime claim. Value/timings must come from test --public, not the probe, which included bootstrap. Download cache grows with repositories/versions; no automatic pruning claimed.

### Key and invalidation

Only standard committed build.sbt.lock is detected/hashed; it records the resolved graph with artifact hashes (dependency-lock official README). Key contribution is existing engine MD5, 32 lowercase hex. This is a download-cache namespace, not a complete arbitrary build identity: missing artifacts may be fetched after build/plugin settings change. Custom cross-version lockfile names, lockless projects, generated locks and independent multi-build aggregation are unsupported; no manifest fallback that would under-hash executable Scala build definitions. Root then one-level shortest match is preserved (command `cat internal/plugin/autodetect/auto_detect_util.go`). Lock changes must invalidate; supplementary source edits need not.

### CI integration

COURSIER_CACHE must be injected into restore/build/save; preparer defaults to workspace/.cache/sbt matching the required env. Until harness-core ships, set it explicitly at stage scope. It moves artifact cache only, not credentials/config/install binaries (Coursier docs). No install-command cache wiring. Bootstrap of sbt itself is intentionally not cached; fresh build images must provide Java/sbt or allow launcher bootstrap. Offline proof uses LocalOnly policies on all application projects; sbt/meta-build initialization can still require online bootstrap outside cached application dependencies.

## Design

### Mapping entry

Insert `globToDetect: "build.sbt.lock", tool: "sbt", preparer: newSbtPreparer()` after the Gradle entries, before Bazel. No extra dirs/hash globs or engine changes. Existing relative legacy mapping order stays unchanged; mixed sbt/legacy keys gain the sbt contribution at this position. Root/one-level shortest match semantics remain from `cat internal/plugin/autodetect/auto_detect_util.go`.

### Paths

| Path | Type | Strategy | Reason |
|------|------|----------|--------|
| COURSIER_CACHE/https | artifact downloads + metadata | follow-only | real probe uses supplied env; only HTTPS URL subtree selected |
| workspace/.cache/sbt/https | artifact downloads + metadata | fallback matching required CI env | no configuration writes |
| target, .sbt, .ivy2, credentials.sbt | outputs, boot, config, secrets | excluded | not beneath selected subtree; see research-probe.log and official cache URL layout |

Relative env resolves against process cwd (Harness workspace), not a detected nested project; use resolveRepoPath and workspaceRoot. Preparers do not create directories, execute sbt or mutate files. Missing cache is expected cold behavior. Evidence: planned tests Test_sbtPreparer_Paths and Test_sbtPreparer_NoMutation; verify via create gate.

## Compatibility and migration

Legacy-only paths and keys must remain byte-identical (baseline autodetect test passed in evidence/baseline.log; full compatibility gate will re-run). Mixed repositories newly containing a recognized build.sbt.lock start cold; intentional additive namespace, no legacy migration. No tracked Scala, JVM options or native config files are rewritten. COURSIER_CACHE affects other Coursier clients in the stage, but not credentials, binaries or config. Native csrCacheDirectory/sbt.coursier.home overrides must agree with it. Sources: research-probe.log, `cat auto_detect_util.go`, and cache documentation fetched during research.

## Limitations

Only committed standard build.sbt.lock files, root or one level deep; no lockless fallback, custom lock names, deep recursive detection or multiple independent build key aggregation (engine inspection in research). Cache HTTPS artifact downloads, never target outputs, sbt/JDK bootstrap installations, Ivy local repos or credential files. Repository URLs must not contain credentials. sbt executable build settings cannot be inferred by the plugin; custom cache overrides and useCoursier=false unsupported. Local proof targets Linux amd64/JDK17/sbt1.12.9 only; cross-compilation is not native-platform evidence. Offline LocalOnly proof covers application resolution after meta-build/launcher initialization, not offline installation of sbt itself (research-offline.log). No performance claim until public lifecycle measurements; no remote validation in this implement phase.

## Rollout and rollback

Release through the normal drone-cache release. Projects that start being detected get a new composite key, so their first run after rollout is cold. Roll back by reverting the mapping entry and preparer; an image rollback alone does not reuse keys created by this change.
